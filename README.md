A URL-only phishing triage console. Paste one address and receive a measured
verdict, the model's probability and confidence, the signals that moved the
score, and observable facts about the address structure.

The classifier is a **classical machine-learning ensemble** trained on a public
phishing URL dataset. It is **not deep learning**: no TensorFlow, Keras or neural
network is involved. The ML verdict is authoritative; scraper / language-model
text is supporting context only.

---

## Features

- Single-purpose interface with six regions: hero, method, checker, report, about and footer.
- Responsive analyst console: fixed rail on desktop, frosted top bar on mobile.
- Verdict, probability, confidence and decision threshold in one report.
- Address structure, domain features and heuristic observations derived from the submitted URL.
- Ranked character n-gram signals with their contribution to the score.
- Model provenance sourced from the saved artifact, not marketing numbers.
- No accounts, no login, no page-content fetch required for the verdict.

## How it works

```
Browser (React)
   │  POST /api/predict  { url_or_prompt, session_id }
   ▼
FastAPI (detect_url/backend/app.py)
   ├── ML inference  ──►  weighted ensemble verdict   (authoritative)
   └── scraper / Gemini agent ──► supporting context  (optional)
   ▼
React report panel
```

The model blends two fitted linear models:

- `0.75 × hybrid_logreg` — `StandardScaler` over 57 numeric URL features plus
  character TF-IDF (2–5 grams).
- `0.25 × char_logreg` — character TF-IDF only.

Decision rule: `p >= 0.5` → `PHISHING`, otherwise `SAFE`.
Confidence is `max(p, 1 − p) × 100`.

## Model facts

Source of truth: [`detect_url/ml/artifacts/metrics.json`](detect_url/ml/artifacts/metrics.json).

| Metric | Value |
|---|---:|
| Held-out accuracy | 93.22% |
| Precision | 94.67% |
| Recall | 91.60% |
| F1 | 93.11% |
| ROC-AUC | 98.35% |
| False-positive rate | 5.16% |
| False-negative rate | 8.40% |
| Unique URLs after de-duplication | 11,429 |
| Train / held-out test | 9,143 / 2,286 |
| Numeric URL features | 57 |
| Majority-class baseline | 50.00% |

`features_used: 58` in a live response means 57 numeric features plus the raw
URL text column consumed by the character vectorizer. It is not a missing or
extra numeric feature.

## Quick start

### Prerequisites

- Python 3.11+
- Node.js 18+
- A Google Gemini API key (for the optional supporting-context layer)

### 1. Backend

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # Windows: copy .env.example .env
# Edit .env and set GEMINI_API_KEY=your-key

python -m uvicorn detect_url.backend.app:app --host 127.0.0.1 --port 8000
```

The API is now available at `http://127.0.0.1:8000`.

### 2. Frontend

```bash
npm install
npm run build                   # writes the SPA into website/
```

Open `http://127.0.0.1:8000/` while the FastAPI server is running.
For development with hot reload, run `npm run dev`; Vite proxies `/api` to
`http://127.0.0.1:8000`.

> The FastAPI app currently requires `GEMINI_API_KEY` at startup. The ML module
> itself (`detect_url.ml.inference`) can be imported and used directly without
> any LLM key.

## API

### `POST /api/predict`

```json
{
  "url_or_prompt": "https://www.google.com",
  "session_id": "default"
}
```

Response shape:

```json
{
  "status": "success",
  "response": "supporting scraper / LLM context",
  "ml": {
    "verdict": "SAFE",
    "is_phishing": false,
    "phishing_probability": 0.0064,
    "confidence": 99.4,
    "threshold": 0.5,
    "signals": ["'.goo' (+0.07)", "'s://w' (-0.26)"],
    "features_used": 58
  },
  "model": { "model": "weighted_ensemble", "accuracy": 93.22 }
}
```

### `GET /api/model`

Returns the saved model card and metrics.

## Verification

```bash
python -B -m detect_url.ml.verify   # re-measures metrics from the raw CSV
python -B -m detect_url.ml.probe    # checks real-world URLs
npm run build                       # frontend production build
```

Known sample outputs:

| Input | Verdict | Probability |
|---|---|---:|
| `https://www.google.com` | SAFE | 0.64% |
| `http://paypa1-login-verify.tk/...` | PHISHING | 99.98% |
| `http://192.168.1.1/secure-banking-login.php` | PHISHING | 99.91% |

## Limitations

- UCI-style destination labels mark Google redirect URLs as phishing, which can
  hurt naive character models on `accounts.google.com`.
- No HTML, WHOIS or traffic features are used at inference; page-content
  phishing signals are outside the model's scope.
- Live redirect validity and TLS certificate validity are not verified by the
  classifier; the report says so explicitly.
- Gemini availability depends on Google's API. When the LLM context is
  unavailable, the ML verdict is still returned.

## Security

No API keys are committed. Secrets live only in the git-ignored `.env` file;
`.env.example` contains a placeholder. The scraper only accepts public HTTP(S)
targets, though redirect re-validation is a recommended hardening step before
exposing the service publicly.
